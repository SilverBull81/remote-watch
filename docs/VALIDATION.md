## Исправления 0.3.5.dev2 по результатам CI

Первый запуск [матрицы 0.3.5.dev1](https://github.com/SilverBull81/remote-watch/actions/runs/36893605290)
выявил ошибку вывода русской справки в Windows с кодировкой cp1252 и остановку
одного Linux-сценария команд с `conflict`. Исправлены кодировка четырёх старых
CLI диагностики и сравнение срока разрешения: обратное вычитание float могло
ошибочно показывать превышение разрешённого времени. Теперь сравниваются
абсолютные границы с одинаковым округлением, без дополнительного допуска.

Добавлены четыре проверки дробных сроков и перехода через границу точности
float: корректный START проходит, увеличение даже на следующий представимый
шаг отклоняется, повторного разрешения на callback нет. Проверка установленного
wheel запускает все семь CLI с принудительной cp1252 и проверяет UTF-8-вывод.
В повторном CI исправлены также ожидания контрактных тестов: чтение SQLite
вынесено из event loop, наблюдение повторяется только при `store busy`.
Сценарий двух приложений использует штатные интервалы повторов, длинный poll
и считает ответы после hub ACK, а не возможные дубликаты отправки. Конечный
предел наблюдения в этом сценарии — 20 с; сроки исполнения команд не менялись.
Ручной TLS-сценарий изолирован от периодического sweep: в нём нет dispatcher,
который в приложении повторяет обмен после штатного `busy`. Конкуренция с sweep
остаётся включённой в сквозных сценариях gateway/dispatcher. Проверки доверия,
имени и срока сертификата, поддельного claim и UNKNOWN/release сохранены.
Тест явной отмены StoreWorker больше не требует создания SQLite за 50 мс:
подготовка имеет обычный конечный срок, а начало блокирующей операции
подтверждается Event. Проверка удержания единственного слота после отмены сохранена.
Итоговый [запуск GitHub Actions](https://github.com/SilverBull81/remote-watch/actions/runs/36899958770)
на коммите `6bee643bf974145a73b51a5625303814c2d1e732` завершился успешно:
**8 из 8 заданий**, без предупреждений pytest. Более поздний коммит с этой
записью меняет только документацию; повторный CI для него не запускался.

| Область | Сценарии | Ожидаемый результат |
| --- | --- | --- |
| Logging | Logger/LoggerAdapter, hierarchy, filters, propagation, чужие handlers | Нет глобальной перенастройки и изменения исходной записи |
| Eligibility | notify true/false/absent, ERROR default, topic/tags/identity | Точные правила, без двойного destination ID |
| Snapshot | Изменяемые args, exception, неверные metadata, oversize | Неизменяемые ограниченные данные, без traceback references |
| Identity | Подмена instance/service через extra | Runtime identity сохраняется |
| Queue | Полный ingress и одно переполненное назначение | Drop без ожидания, другие назначения продолжаются |
| Scheduling | Retry storm, bridge wakeups, несколько producers | Общий outstanding budget не обходится callbacks/tasks |
| Delivery | Accepted, transient/permanent failure, malformed reply, unknown | Правильная классификация и безопасная диагностика |
| Retry | Attempts, jitter, retry-after, TTL | Конечные попытки, нет повторов после expiry |
| Isolation | Slow/failing channel рядом со здоровым | Здоровый обслуживается независимо |
| Recursion | Worker, adapter, HTTP dependency и diagnostic sink logs | Не возникают новые remote notifications |
| Secrets | Config repr, ошибки HTTP, redactor, tokens в URL | Собственные credentials не появляются в снимках/диагностике |
| Lifecycle | До start, duplicate start, stop до start, startup failure | Явные состояния, корректный rollback ресурсов |
| Shutdown | Full queue, retry wait, active send, concurrent producers | Закрытие приёма, общий deadline, discard/unknown accounting |
| Async | Логирование из приложения с asyncio, async shutdown | Не захватывается и не блокируется main loop доставкой |

Clock и random source подменяются в unit-тестах; retry-тесты не ждут реальные
минуты. Настоящие concurrency-тесты используют barriers/events и конечные deadlines,
а не хрупкие ожидания по короткому sleep. Проверки воспроизводимы и не требуют сети.

Contract suite для custom adapters проверяет lifecycle в одном loop, одну попытку
на send, cancellation, классификацию ошибок и отсутствие скрытого retry.
Синхронно блокирующий/игнорирующий отмену адаптер контракту не соответствует.
