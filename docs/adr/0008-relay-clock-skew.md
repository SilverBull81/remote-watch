# ADR 0008: явный допуск расхождения часов outbound relay

Version 1.0.0

Автор: Sergey Fundobny (silverbull@mail.ru) + GPT-6

Дата и время последнего изменения: 260930-164943

## Причина и статус

В ходе настройки RU → LV пользователь сообщил: часы LV опережают RU больше чем
на минуту; расхождение меняется, синхронизация через IT пока недоступна.
TLS и авторизация запроса прошли, но минутный smoke получил relay_expired.
Старый future_tolerance помогает только при опережении часов отправителя.

Реализовано в 0.2.0.dev9. Проверки с заданными часами используют loopback HTTP
и подставной provider. Доставка через исправленный gateway на целевых VM
ещё требует пользовательского smoke. Решение уточняет UTC-проверки
[ADR 0006](0006-gateway-admission-and-lifecycle.md).

## Решение

В GatewayConfig и JSON gateway добавлен clock_skew_tolerance: конечное число
секунд от 0 до 3600 включительно, по умолчанию 0. Оно не передаётся клиентом.
Wire schema 1/2 не меняются; обновление клиента для допуска не требуется.
Настройка действует на все principals данного gateway и только на outbound relay.

При проверке события сервер прибавляет допуск к двум остаткам, вычисленным
по UTC разных машин: expires_at − server_now и destination.ttl − возраст события.
created_at не может опережать server_now больше чем на
max(clock_skew_tolerance, future_tolerance). Допуски не складываются.
Старый future_tolerance сохраняет предел 30 секунд и односторонний смысл.
Исходные created_at/expires_at и текст уведомления не переписываются.

Попытка по-прежнему ограничена минимумом: timeout − elapsed,
remaining_ttl − elapsed, двух указанных UTC-остатков с допуском,
server/destination attempt_timeout и destination.ttl. elapsed измеряется
монотонными часами с момента приёма gateway. Допуск не прибавляется
к относительным срокам клиента, таймаутам или времени обработки.
Runtime клиента продолжает ограничивать очередь и повторы своим сроком.

Исчерпанный срок возвращает relay_expired и увеличивает expired.
Событие из будущего сверх допуска возвращает relay_clock_skew и увеличивает
clock_skew, а не expired. Оба результата — permanent_failure до provider send.
Они поддерживаются обеими wire schema без добавления полей. Одноразовый smoke
показывает эти известные коды и фиксированные пояснения; произвольные строки
reason_code из сети не печатаются.

## Цена и границы

Допуск не измеряет и не исправляет часы. Сервер не способен отличить задержанное
сообщение от свежего с отстающей машины в пределах разрешённого окна. Таким образом,
UTC-отсечение старых запросов ослабляется на выбранный допуск; защита от повторного
воспроизведения не появляется. Настройку задают явно по реальному расхождению
с небольшим запасом, а не включают для всех установок по умолчанию.

Неограниченное отключение expiry и увеличение TTL только у smoke отвергнуты:
первое убирает серверную границу возраста, второе оставляет проблему у приложений.
Автоматическая оценка смещения потребовала бы отдельного протокола и обработки
задержек/скачков часов; для текущего outbound relay выбран ограниченный допуск.
При расхождении больше часа или больших скачках нужна отдельная диагностика.

Это не решение для TLS validity или будущих команд. Контур команд потребует
собственного определения срока и защиты от повторов; допуск outbound нельзя
автоматически переносить на выполнение действий в приложениях.
