# ADR 0015 — подготовка установки без изменения рабочего состояния

Version 1.0.0

Автор: Sergey Fundobny (silverbull@mail.ru) + GPT-6

Дата и время последнего изменения: 261013-180233

Статус: реализовано в 0.4.3.dev1 по согласованному этапу server deploy.

## Решение

CLI remote_watch.gateway_server.deploy и модуль gateway_server.deployment
создают комплект из package resources. Deploy не получает credentials и не
запускает Python/Caddy для проверки, не читает источники команд и не открывает
SQLite. Параметры нового комплекта задаются явно, отдельный dry-run не пишет ничего.

Для существующих компонентов записываются абсолютные ссылки на прежние JSON:
это сохраняет их базу относительных путей. Содержимое не копируется и не мигрирует.
Default external Caddy соответствует действующей службе LV. Managed требует
явных executable/data_dir и сохраняет указанный старый Caddyfile. Новый шаблон
не является автоматическим предложением сменить действующий CA.

Существующие файлы никогда не заменяются, даже если совпадает прежний manifest.
Обновление создаёт отдельные предложения templates/версия и сравнение по именам
файлов. Строковый diff реального конфига не выводится: в нём могут быть секреты.
Автоматического слияния пользовательских JSON в первом варианте нет.

Запись ограничена фиксированными именами комплекта; symlink/junction в целевых
путях отвергаются, O_EXCL защищает от конкурентного появления файла. Это не
транзакция файловой системы: при отказе носителя возможно частичное создание;
автоматического удаления и восстановления старого состояния нет. Каталог должен
находиться под контролем оператора. Чужие процессы не останавливаются.

Шаблоны новых конфигов используют token_env с разными именами секретов для двух
каналов. Оператор вправе заменить token_env на token. Генерация секретов не входит
в первую итерацию: нет встроенного общего действующего секрета и вывода credentials.
Скрипты фиксируют Python, а manifest/START_HERE — версию библиотеки; pip install
и загрузка исполняемых файлов при старте не выполняются.

## Проверка и границы

Проверяются новая/существующая установка, dry-run, повтор, отдельные обновления,
Unicode/пробелы, файлы с приватным содержимым, links/junction, O_EXCL, согласованные
порты и Identity. Из чистых core/extras wheel проверяются package resources,
реальный CLI и check-config без сети. Реальный shell запускает только проверку
JSON. Преобразование синтетического Caddyfile проверяется отдельно от TLS/продления.

Установка служб и doctor остаются этапами 0.4.5/0.4.4. Инструкция:
[GATEWAY_DEPLOY.md](../GATEWAY_DEPLOY.md). Полевые проверки выполняются владельцем.
