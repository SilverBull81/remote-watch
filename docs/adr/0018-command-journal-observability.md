# ADR 0018: наблюдение командных журналов без нового владельца

Version 1.0.0

Автор: Sergey Fundobny (silverbull@mail.ru) + GPT-6

Дата и время последнего изменения: 261014-113001

Статус: реализовано в 0.4.4.dev5; полевая проверка новых сводок отдельно.

Для остатка R5 нужны ёмкость и состояния command journals. Обычный Store.open()
может восстановить UNKNOWN, сменить generation и открыть journal новым владельцем.
Поэтому диагностический вызов его не использует.

Работающий StoreWorker наблюдает собственное хранилище после обычных операций,
не чаще одного раза в 5 секунд. Дополнительной очереди задач нет; один executor
остаётся занят до окончания всей операции. SQL-наблюдение ограничено 50 мс с
progress handler, не ждёт чужого writer и откатывает только свою read transaction.
Исходная операция, включая успешный commit, не меняет результат из-за сбоя сводки.
Кэш имеет явные доступность и возраст. Остановка/старый heartbeat не обнуляют возраст.
Исход и монотонное время реальной операции фиксируются отдельно от наблюдения.
Её своевременный commit не становится timeout из-за позднего диагностического I/O.
Executor остаётся pinned до окончания чтения. При max_waiters=0 допускается один
ограниченный waiter только на фазе наблюдения; обычная занятость реальной записью
сохраняет немедленный busy. Для hub прежний bounded FIFO не расширяется.

Hub/client/source предоставляют только агрегаты. Из command metadata читаются
сохранённые числовые лимиты; source owner передаёт runtime seen_limit. Остановленный
source-файл не содержит этих лимитов: неизвестное остаётся null. Резерв payload
отделён от действительного объёма. UNKNOWN и execution_active не отождествляются
с живым callback и не освобождаются автоматически.
Общее число UNKNOWN отделено от UNKNOWN без административного решения, чтобы
сохранение истории после явной сверки не порождало повторное предупреждение.

Приватный локальный IPC status расширяется необязательным journals с hub и не более
8 источников. Схема строго проверяет поля, категории и числа; нет имён источников,
Identity, cursor, аргументов, результатов, токенов или путей. Heartbeat ограничен
16 KiB; control-запрос сохраняет 4 KiB, общий предел 8 обработчиков и прежнюю auth.
Manager отдаёт кэш. Doctor server --online не открывает SQLite. Внешние endpoints
doctor/commands не получают сведения всего hub и не меняют wire/ACL/сессии.

Явный doctor --mode journal читает остановленный локальный файл как immutable/ro,
отказывает при sidecar/неизвестной схеме, не создаёт БД, locks и recovery.
Это не способ читать живой изменяемый файл; для него предусмотрен кэш владельца.
SQLite-схемы не меняются. Сводки не удаляют доказательства и не повторяют callbacks.
Предупреждения capacity/UNKNOWN/stale отделены от готовности сервиса и его restart.
