# ADR 0010: wire, время и переходы команд 0.3.1

Version 1.0.0

Автор: Sergey Fundobny (silverbull@mail.ru) + GPT-6

Дата и время последнего изменения: 260930-193650

## Решение и статус

В 0.3.0.dev1 реализованы независимые от сети модели и чистые проверки контракта
[COMMAND_PROTOCOL.md](../COMMAND_PROTOCOL.md). Это конкретизация
[ADR 0009](0009-command-scope-and-safety.md); SQLite/исполнение ещё не добавлены.

Приняты строгий JSON schema_version=1 с закрытым kind, явные session/hub epochs,
единственный claim, хеш полного запроса и квитанция хеша результата. Пределы
байтов/команд/аргументов/времени проверяются при создании моделей и чтении wire.
Capabilities отделены от callback. Прежний CommandRegistry/CommandContext совместим.

Время авторизации не использует UTC разных VM. Hub выдаёт оставшийся бюджет,
клиент вычитает полное время запроса своими monotonic-часами. После рестарта сроки
не восстанавливаются с нуля. READY/CLAIMED закрываются как EXPIRED, STARTED — UNKNOWN.
Уже выданное ограниченное разрешение нельзя мгновенно отозвать у отключённого клиента;
это одна из причин UNKNOWN. Новое поколение не перевыдаёт старую попытку.

Исходный вариант свежести изменяющего намерения — одноразовое actor/chat-bound
подтверждение с локальным окном hub до 30 секунд. Оно проверяется без часов Telegram
и RU. Удобство UX уточняется у владельца; Telegram UI ещё не реализуется. Молча
считать время получения первоначального сообщения временем намерения отвергнуто:
так старый resume может выполниться после долгого обрыва связи.

STARTED фиксируется на hub до grant и на клиенте до callback. Переход допускает
единственный запуск только после atomic commit; чистая модель сама commit не делает.
При потере подтверждения можно повторить запрос состояния/передачу результата,
но нельзя повторить callback. Это относится и к read-only/idempotent.

None/короткий str — completed callback, не подтверждение завершения бизнес-операции.
Неверный результат/исключение/timeout после начала — UNKNOWN с фиксированным reason,
без str/repr чужих объектов и без traceback. Терминальный UNKNOWN не переписывается
поздним противоречащим результатом; фактическое состояние уточняется новой командой.

## Последствия

Core остаётся без runtime-зависимостей. Полный объём 0.3 не объявляется готовым:
auth, постоянная защита от повторов, storage CAS, executor и сеть ещё впереди.
Чистые модели уже позволяют проверить границы и переходы без Telegram и credentials.
Параметры адресации, локальные callbacks и их loop остаются вне wire; обработка
читаемых aliases и Telegram parser будет добавлена вместе с transport/dispatcher.
