# ADR 0011: одна команда, достоверное время и постоянный журнал

Version 1.0.0

Автор: Sergey Fundobny (silverbull@mail.ru) + GPT-6

Дата и время последнего изменения: 260930-220144

## Решение и статус

Владелец одобрил проверку возраста сообщения вместо обязательного подтверждения
resume/suspend. В 0.3.0.dev2 реализованы [компоненты времени](../COMMAND_TIME.md)
и [этап 0.3.2](../COMMAND_STORAGE.md). Дополняется
[ADR 0010](0010-command-wire-time-and-transitions.md).

Hub использует доверенную оценку UTC с явной погрешностью, сроком годности и
дрейфом. Возраст вычисляется консервативно; дальше передаётся только остаток
монотонного срока. Отсутствие достоверной оценки закрывает приём команды.
Ни синхронизация всех VM, ни изменение системных часов не требуются.
Исходные значения: возраст 120 с, оценка времени 300 с, ширина интервала до 5 с.
HTTPS Date допустим только от явно доверенного origin с заявленной accuracy;
универсального автоматически выбранного сервиса нет. Живой источник ещё
предстоит настроить и проверить при внедрении командного hub.

SQLite сохраняет решение источника и его cursor в одной транзакции. Источник
подтверждается после commit. STARTED фиксируется до grant/callback; сравнение
revision защищает от конкурирующих исполнителей. Неопределённый исход commit
не выдаёт разрешения на действие. После рестарта STARTED становится UNKNOWN.

Основой защиты после очистки payload служит постоянная возрастающая позиция
потока. Повтор не может получить новую позицию. Provider cursor, который не
подчиняется этому контракту, требует явного сопоставления в адаптере.
Сброс Telegram update_id после простоя нельзя скрыть простым обнулением БД.

Логическая ёмкость резервирует будущий результат при приёме команды. Физические
страницы SQLite, число записей/потоков, аудит и ожидание блокировок ограничены.
Для простого локального владельца выбран rollback journal с FULL synchronous;
неограниченный WAL за медленным читателем не нужен. Очистка не удаляет команды
без ACK или с возможным активным callback. Для последнего нужна отдельная
подтверждённая отметка окончания, даже после UNKNOWN и истечения retention.

## Последствия

Сеть команд, ACL, регистрация, executor и Telegram source остаются этапами
0.3.3–0.3.5. Прототип подтверждения сохранён, но не обязателен и не подключён.
Новый таймер не выдаёт готовую гарантию точности произвольного интернет-сервера.
Журнал не обеспечивает exactly-once бизнес-операции, не останавливает sync callback
и не поддерживает восстановление защитных записей из устаревшего backup.
Неопределённая попытка может занимать место до явной сверки; новые команды при
переполнении отклоняются. Это выбранное поведение, а не молчаливое удаление защиты.
