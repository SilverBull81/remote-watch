# ADR 0004 — команды принадлежат приложению

Version 1.0.0

Автор: Sergey Fundobny (silverbull@mail.ru) + GPT-6

Дата и время последнего изменения: 260928-110519

Статус: регистрационный контракт реализован; transport/dispatcher отложены.

## Контекст

Пользователь уже связывает имена resume_load/suspend_load/check_load с partial,
передавая события приложения. Будущий watcher должен принимать весь пользовательский
набор команд при создании, а не ограничиваться встроенным списком операций.

## Решение

WatcherConfig.commands принимает mapping имён на callbacks без оставшихся обязательных
аргументов либо неизменяемый CommandRegistry из CommandSpec. Поддерживаются sync/async
функции, bound methods, callable objects и partial. Для контекста запроса нужен
явный takes_context; сигнатура не угадывается во время выполнения.

CommandSpec хранит описание, required scope, timeout, read_only/idempotent и
необязательный валидатор именованных строковых аргументов. По умолчанию аргументы
не разрешены, read_only/idempotent False, требуемое право command:<name>.
Регистрация не вызывает callback/validator, не запускает входящий transport и не
означает выдачу прав. Функции и привязанное состояние остаются в приложении.

Контракт исходящего канала уточнён до send(Delivery): стабильный delivery ID и
номер попытки передаются вместе с Notification. Это сохраняет общую границу
для прямого канала и будущего relay без provider-specific параметров в core.

## Альтернативы

- Только словарь: достаточно для Event, но не выражает политику и валидацию аргументов.
- Только command subclasses: лишнее наследование для нескольких простых функций.
- Авто-discovery/decorators: можно добавить позже поверх явного registry; сейчас
  не нужны глобальная регистрация и побочные эффекты импорта.
- Выполнение команд в delivery loop: связывает произвольную логику приложения
  с надёжностью уведомлений и нарушает разделение контуров.

## Последствия

Пользовательский паттерн сохраняется без legacy TelegramBot shim. Расширенный
контракт не требует messenger-specific callback arguments. Первый сетевой status
проверяет инфраструктуру, а не ограничивает публичный список команд.
До dispatcher нужны auth/ACL, expiry/replay/audit и явный executor contract,
особенно для async loop affinity и синхронных таймаутов.
