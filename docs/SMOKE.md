## Запуск

После установки `python -m pip install -e ".[telegram,ntfy]"` из корня проекта:

```powershell
python -m remote_watch.smoke telegram
```

Либо, когда настроен ntfy:

```powershell
python -m remote_watch.smoke ntfy
```

Каждая команда отправляет **одно** синтетическое сообщение только выбранному сервису.
Новый запуск создаёт свежие время UTC и event/session/delivery IDs. В сообщении
указаны INFO, remote-watch-smoke и явные тестовые сведения о размещении.
Smoke не читает рабочие логи и не повторяет запрос автоматически.

По умолчанию читается `credentials.local.json` из **текущего каталога**.
Произвольный поиск файла в родительских каталогах не выполняется. Другой путь:

```powershell
python -m remote_watch.smoke telegram --credentials C:\Private\remote-watch.local.json
```

Результат в терминале не содержит токен, chat/topic, endpoint или содержимое файла.
Коды завершения: 0 — сервис принял сообщение; 1 — отказ или неизвестный исход;
2 — ошибка настройки/файла/зависимости; 130 — прерывание пользователем.
При успехе проверьте сообщение на телефоне: API не подтверждает его показ или прочтение.

## Локальный файл

Поддерживается уже используемая структура `telegram.token` / `telegram.chat`.
Для ntfy предпочтительно поле `topic`; `chat` тоже поддерживается как прежнее имя.
Пустая секция ntfy не мешает запуску Telegram. Сам файл smoke не изменяет.

Пример структуры с **вымышленными значениями**; замените их только в локальном файле:

```json
{
  "telegram": {
    "token": "<TELEGRAM_BOT_TOKEN>",
    "chat": "-123456789"
  },
  "ntfy": {
    "endpoint": "https://ntfy.example.com",
    "token": "<NTFY_ACCESS_TOKEN>",
    "topic": "remote-watch-alerts"
  }
}
```

Telegram также принимает `chat_id` и необязательный `message_thread_id`.
Endpoint по умолчанию: официальный Bot API для Telegram и ntfy.sh для ntfy.
Для собственного сервера без TLS можно явно задать `allow_http: true`;
обычный сценарий использует HTTPS. Для обоих smoke требуется непустой token.

Файл исключён `.gitignore` и правилами сборки. Не добавляйте его через `git add -f`.
Значения не передаются в аргументах процесса, дочерние процессы не создаются.
Для существующего контракта адаптеров smoke временно создаёт отдельную переменную
окружения внутри своего процесса и удаляет её при завершении, ошибке или отмене.
Исходное окружение пользователя и его постоянные настройки не меняются.

Это формат **ручного smoke**, а не новый обязательный формат конфигурации библиотеки.
Приложения по-прежнему используют типизированные настройки из [ADAPTERS.md](ADAPTERS.md).

## Подготовка ntfy

Пошаговая настройка для ntfy.sh и собственного сервера: [NTFY_SETUP.md](NTFY_SETUP.md).
Токен относится к учётной записи на конкретном сервере; topic — имя канала на нём.
Токен ntfy.sh нельзя использовать на другом сервере ntfy.

## Relay, начиная с 0.2.0.dev1

Для совместимого gateway добавлена команда `python -m remote_watch.smoke relay`.
Она использует extra relay и отдельную секцию credentials `relay` с endpoint, alias
и сервисным token. Сервер 0.2.0.dev3 настраивается по [GATEWAY_SERVER.md](GATEWAY_SERVER.md);
нужно разрешить точную синтетическую Identity smoke. Схема и границы готовности
описаны в [RELAY.md](RELAY.md). Короткие Telegram/ntfy smoke продолжают работать как раньше.
