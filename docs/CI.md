## Одна команда для выбранной среды

В Python, который требуется проверить, установите build; глобальный Python менять
не нужно. Затем из корня checkout выполните:

```powershell
python -m pip install build
python tools/validate.py --mode core --output build/check-core-01
python tools/validate.py --mode extras --output build/check-extras-01
```

Каталог вывода должен быть новым и находиться внутри build. Он не перезаписывается
и не удаляется автоматически. Каждый запуск строит sdist/wheel, затем отдельный
wheel из sdist, проверяет состав архивов и совпадение установочных исходников,
создаёт чистый venv и устанавливает только выбранные зависимости.
До установки тестовых пакетов проверяются отсутствие обязательных зависимостей,
ленивые импорты, py.typed, отсутствие потоков/изменений root logger и cryptography
в рабочем окружении. В режиме extras открывается и закрывается HTTP-клиент без
внешнего запроса; core проверяет понятную ошибку отсутствующего extra.

Затем устанавливаются pytest/cryptography и запускаются unit/contract tests
с `-I` и отключённым `pythonpath=src`: тестируется установленный wheel, а не checkout.
Live-тесты исключены; переменные REMOTE_WATCH_* из родительского окружения удалены
для дочерних проверок. Настоящие credentials не нужны и не читаются инструментом.
Во время установки пакетов нужен доступ к индексу; сами тесты используют только
подставные каналы и loopback. Каждый дочерний этап ограничен десятью минутами.

Результат — report.json с версиями Python/пакета/ОС и кодами этапов, tests.xml
и отдельные локальные логи. Код 0 и passed=true означают успех всех шагов.
При ошибке предыдущие логи сохраняются, дальнейшие шаги не запускаются.
Запускайте проверки одного checkout последовательно: setuptools использует общий build.

## GitHub Actions

[validation.yml](../.github/workflows/validation.yml) задаёт восемь сочетаний:
Windows/Linux × Python 3.10/3.12 × core/extras. Каждое работает в отдельном job,
исполняет Ruff и ту же tools/validate.py. События — push, pull_request, workflow_dispatch.
Права токена ограничены чтением содержимого; секреты провайдеров не передаются.
Логи и отчёты сохраняются на семь дней, установка пакета или публикация релиза
за пределами тестовых сред не выполняются.

Это минимальная проверяемая матрица, а не обещание тестирования каждой версии Python
или каждого дистрибутива Linux. Добавление workflow не означает его успешный запуск.
Для закрытия пункта №4 review нужны зелёные восемь jobs конкретного коммита;
сохраните ссылку на run и его SHA. На машине разработки без Linux его результаты
не подменяются проверкой синтаксиса Python 3.10.

Текущие фактически выполненные проверки фиксируются в [VALIDATION.md](VALIDATION.md).
Источники: [setup-python](https://github.com/actions/setup-python),
[upload-artifact](https://github.com/actions/upload-artifact).
