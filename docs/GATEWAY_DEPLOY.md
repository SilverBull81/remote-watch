# Подготовка установки gateway server

Version 1.0.0

Автор: Sergey Fundobny (silverbull@mail.ru) + GPT-6

Дата и время последнего изменения: 261013-180233

Этап **0.4.3**, версия **0.4.3.dev1**. Команда
`python -m remote_watch.gateway_server.deploy` создаёт файлы установки из ресурсов
wheel, без checkout, сети, запуска компонентов и обращения к журналам команд.
Она работает и с новой папкой, и рядом с существующей установкой.

## Текущая LV VM: подключить прежние конфиги

Обновите выбранный venv до проверенной версии remote-watch с extras
`gateway,commands,telegram,ntfy` и при необходимости `tray`. Если устанавливаете
из Git, фиксируйте commit, а не обновляйте main при каждом запуске.
Перед обновлением приложений учтите [переименования API и JSON](NAMING_MIGRATION.md).

Ниже сохранены известные из настройки имена старых файлов. Если реальные имена
отличаются, замените только соответствующие пути. Внешний адрес должен совпадать
с именем/IP действующего TLS-сертификата; вместо АДРЕС_LV укажите свой адрес.

```powershell
C:\Work\RemoteWatch\.venv\Scripts\python.exe -m remote_watch.gateway_server.deploy --directory C:\Work\RemoteWatch --endpoint https://АДРЕС_LV:8443 --notifications-config C:\Work\RemoteWatch\gateway_config.json --commands-config C:\Work\RemoteWatch\command_gateway.json --dry-run
```

Preview перечислит планируемые файлы и ничего не запишет. Повторите ту же команду
без `--dry-run`, затем:

```powershell
Set-Location C:\Work\RemoteWatch
.\check-config.ps1
```

Проверьте gateway_server.local.json: он должен ссылаться на прежние конфиги,
использовать порты 8765/8766 и `caddy.mode: external`. Для уже работающей службы
RemoteWatchCaddy это основной вариант. Служба сохраняет свой CA, каталог данных,
учётную запись и Caddyfile; новый Caddyfile.example поверх него не копируется.

После успешной проверки остановите два прежних отдельно запущенных Python gateway.
Остановку действующей системы deploy не выполняет. Затем запустите:

```powershell
.\start.ps1
```

В другом окне доступны `.\status.ps1` и `.\stop.ps1`. Start остаётся работающим
процессом; до этапа службы ОС не закрывайте его окно/RDP-сессию с завершением
процессов. Для трея задайте application.ui=tray и установите extra tray.

Сначала проверьте уведомления и команды каждого приложения, затем рестарт manager
и reconnect клиентов с прежними журналами. При UNKNOWN возможна намеренная
блокировка повторной регистрации: это защита от повторного исполнения callback,
а не повод очищать SQLite. Подробности: [COMMAND_RECONNECT.md](COMMAND_RECONNECT.md).

## Новая установка

```powershell
python -m remote_watch.gateway_server.deploy --directory C:\Work\RemoteWatchTest --endpoint https://АДРЕС_LV:8443
```

Без дополнительных флагов создаются конфиги уведомлений Telegram/ntfy и команд
Telegram для одного приложения с согласованной Identity. Это **шаблоны**:
токены/chat/actor/topic и реальные Identity задаёт оператор. Имена token_env
можно заменить ключами token с приватными значениями. В образцах нет рабочего
универсального секрета. Для новых закрытых ntfy-команд используйте отдельный
[пример источника](examples/command_gateway.ntfy.example.json) и его правила ACL;
существующий конфиг ntfy подключается через --commands-config без преобразования.

Комплект содержит:

- gateway_server.local.json и конфиги включённых компонентов;
- clients/command_client.example.json и памятку notification_client.example.json;
- Caddyfile.example, либо новый Caddyfile в явно выбранном managed-режиме;
- start/stop/status/check-config в вариантах .ps1 и .sh;
- START_HERE.md с настройкой, запуском, обновлением и полевыми проверками;
- deploy-manifest.json с версией пакета и SHA-256 подготовленных шаблонов.

Manifest — инвентарь предложенных файлов, а не разрешение перезаписывать найденное.
Пример notification_client не является новым JSON API: его поля переносятся в
конфиг приложения/NotificationGatewayClientConfig согласно START_HERE.
Для новых CA клиенты доверяют root.crt; ключи CA и серверные leaf-сертификаты
им не передаются. Проверка TLS остаётся включённой.

## Параметры

| Параметр | Значение |
| --- | --- |
| --directory | Папка комплекта, обязательна |
| --endpoint | Общий внешний HTTPS origin, обязателен |
| --python | Интерпретатор скриптов; по умолчанию тот, которым вызван deploy |
| --components | both по умолчанию, либо notifications/commands |
| --notifications-config / --commands-config | Прежние файлы: сохранить на месте, записать абсолютные ссылки |
| --notification-port / --command-port | Внутренние loopback-порты, 8765/8766 по умолчанию |
| --ui | headless по умолчанию или tray |
| --caddy-mode | external по умолчанию или managed |
| --caddy-executable / --caddy-data | Обязательные явные пути в managed-режиме |
| --caddy-config | Прежний Caddyfile для managed; без него создаётся новый |
| --dry-run | Только сравнить, не создавать даже целевую папку |
| --update-templates | Предложения в templates/версия, рабочие пути не изменяются |

Пути CLI считаются относительно текущей папки. Пути существующих component JSON
сохраняют собственную базу. Скрипты запуска не зависят от текущей папки оператора.
Версия/наличие пакета в ином --python не проверяются запуском чужого процесса:
подготовьте это окружение отдельно. External Caddy не принимает managed-пути.

В managed-режиме прежний Caddyfile должен явно задавать абсолютный filesystem
storage, совпадающий с --caddy-data. Переход со службы на managed не автоматический;
для текущей LV-схемы он не требуется. Настройки шаблона основаны на
[Caddy storage](https://caddyserver.com/docs/caddyfile/options#storage) и
[маршрутизации handle](https://caddyserver.com/docs/caddyfile/directives/handle).

## Повторная подготовка и безопасные отличия

`create` означает отсутствующий файл, `identical` — совпадение, `preserved` —
отличающийся существующий файл, который оставлен без изменений. При --dry-run
create означает только план. Реальные токены, пути из конфигов и содержимое файлов
в отчёт не выводятся. Различия показываются на уровне файлов, без строкового diff
приватных JSON. В режиме обновления current_preserved относится к рабочему файлу,
а отдельный create/preserved — к предложению в templates/версия.

Новые предложения не заменяют конфиг автоматически: перенос нужных полей остаётся
явным действием оператора. Они рассчитаны на основную папку установки, поэтому
не запускайте manager прямо из templates/версия. Повтор предложения той же версии
тоже не перезаписывает существующий файл.

Deploy отвергает symlink/junction в путях записи. Все создания используют O_EXCL;
конкурентно появившийся файл не затирается. Целевой каталог должен принадлежать
оператору: инструмент не предназначен для папки, которую параллельно меняет
недоверенный процесс. Windows-файлы наследуют ACL каталога; права старых файлов
не изменяются. На POSIX новые файлы закрыты для других пользователей.

При сбое записи возможен неполный комплект: созданные файлы не удаляются, существующие
не откатываются. Исправьте причину и проверьте комплект перед повтором; неполный
существующий файл тоже сохраняется. CA/SQLite/locks не создаются и не копируются.

Установка службы, Firewall, доверия CA в ОС и doctor относятся к следующим этапам.
Подготовка файлов не доказывает HTTPS ingress или доставку на телефон.
