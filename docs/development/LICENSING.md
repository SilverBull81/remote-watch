## Зависимости: что требуется сейчас

Core не имеет обязательных runtime-зависимостей. Extras устанавливают сторонние
пакеты через pip; библиотека не включает их исходники/бинарники в свой wheel.
Собранный wheel содержит MIT проекта; установленные distributions зависимостей
содержат собственные license files. Их нельзя удалять или заменять текстом MIT.

Проверенная Windows CPython 3.12 extras-сборка использовала прямые зависимости:

| Пакет | Версия | Лицензия по metadata поставки |
| --- | --- | --- |
| aiohttp | 3.14.5 | Apache-2.0 AND MIT |
| pystray | 0.19.5 | LGPLv3 |
| Pillow | 12.3.0 | MIT-CMU |
| pywin32 | 312 | PSF |

Это снимок конкретного окружения, не фиксированный перечень всех будущих версий.
Перед выпуском проверяют также транзитивные зависимости выбранного окружения
и сохранение файлов лицензий в реально передаваемом комплекте. Для обычной установки
через pip покупать отдельные лицензии на перечисленные пакеты не требуется.

## Если появится единый EXE или комплект с включёнными зависимостями

Такой формат сейчас не выпускается. Для него нужно сохранить copyright/тексты
лицензий и применимые notices всех включённых компонентов. Для LGPL pystray отдельно
обеспечивают выполнение условий соответствующего способа объединения/распространения,
в том числе доступность соответствующего исходного кода библиотеки и возможность
её замены пользователем; упаковщик EXE сам этого не гарантирует. Это не означает,
что весь собственный код Remote Watch обязательно становится LGPL.

Первоисточники: [pystray](https://github.com/moses-palmer/pystray),
[LGPL-3.0](https://www.gnu.org/licenses/lgpl-3.0.html).
Проверка конкретного самостоятельного комплекта выполняется при его подготовке.

## Версия и теги первого стабильного выпуска

Владелец утвердил **1.0.0** и аннотированный тег **v1.0.0** на проверенном release commit.
Основные notifications/commands/gateway возможности приняты в реальном приложении;
номер 1.0 выражает готовность поддерживать публичный API, а не отсутствие ошибок.
0.5.0 больше подходит для периода ожидаемых несовместимых изменений API.

В ветке 1.x: 1.0.1 — совместимые исправления, 1.1.0 — совместимые расширения;
несовместимые изменения публичного API требуют 2.0.0. Для предварительной проверки
release-кандидата допустим 1.0.0rc1 и тег v1.0.0rc1. Уже опубликованные теги не
перемещают. Публикация выполняется в GitHub Release с wheel, sdist и
контрольными суммами. Публикация на PyPI и единый EXE сейчас не планируются. Правила соответствуют [SemVer](https://semver.org/).
