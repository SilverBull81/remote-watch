## Файлы и шапки

Python/Markdown — UTF-8 с BOM и CRLF; JSON/TOML — UTF-8 без BOM и CRLF.
Shell scripts сохраняют требуемый исполнителем формат. Python начинает с назначения,
далее строки `#`, Version A.B.C, автор и модель, timestamp по Москве YYMMDD-HHMMSS.
Между полями метаданных строка `#`. Затем иерархический перечень сущностей: классы,
группы методов, функции/вложенные функции, тесты, exports. Нет пустых секций.

Новый файл — 1.0.0. Содержательная правка повышает независимую file version и timestamp.
В B/C одна цифра: 1.0.9 → 1.1.0. Package version отдельно в pyproject.toml.
Markdown metadata следует за заголовком. В перечне только реальные сущности;
методы сгруппированы под своим классом. __init__.py перечисляет exports.

## Секции и разделители

Крупные секции ИМПОРТ/КОНСТАНТЫ/КЛАССЫ/ФУНКЦИИ/ТЕСТЫ/ЭКСПОРТ ограничены строками
`#***...`. Перед секцией две пустые строки, после её баннера — одна.
Каждый класс/метод/функция имеет собственный трёхстрочный баннер из дефисов,
русское назначение и закрывающий разделитель. Между блоками одной группы — одна
пустая строка. Закрытие предыдущего блока не заменяет открытие следующего.

Вложенные закрытия изнутри наружу: разделитель последнего метода с отступом,
затем разделитель класса без отступа. Аналогично для вложенной функции.
Служебный main guard тоже имеет **верхний** разделитель, строку назначения и нижний.
Нельзя удалять одинаковые разделители, принадлежащие разным блокам.

## Порядок методов

1. `__init__` — КОНСТРУКТОР.
2. Public/property — ИНТЕРФЕЙС.
3. Остальные `__x__` — СПЕЦИАЛЬНЫЙ МЕТОД.
4. `_x` — СЛУЖЕБНЫЙ МЕТОД.

Та же группировка — в шапке файла. Внутренняя свободная `_x` получает СЛУЖЕБНАЯ
ФУНКЦИЯ, публичная — ФУНКЦИЯ, тест — ТЕСТ. Нестандартные short overrides/Protocols
не освобождают от объяснения назначения и типов.

## Сигнатуры и docstrings

Все аргументы вертикально, включая единственный self/cls. Без аргументов допустима
короткая сигнатура. Закрывающая скобка стоит на уровне аргументов, не def.
Перед function docstring — пустая строка; class docstring сразу после class.
Открывающие тройные кавычки на отдельной строке, английский текст — со следующей.

```python
def select_target(
    name: str,
    ) -> str:

    """
    Resolve one explicitly selected target.

    :param name: Configured target alias.
    :type name: str

    :return: Authorized target alias.
    :rtype: str
    """

    # name — заранее выбранный alias, не поиск единственного живого экземпляра.

    return name
```

Каждому явному аргументу соответствует `:param` и `:type`; между парами пустая строка.
Для не-None return — осмысленные `:return`/`:rtype`, не повтор первого предложения.
Перед телом — русские пояснения аргументов, затем **пустая строка**.
Docstring описывает контракт; комментарии объясняют блоки, владение, причины и риски.
Не пишите «Выполнение операции» или «значение для операции» вместо смысла.

## Dataclass и читаемость

Все поля описаны в английском class docstring парами param/type и имеют русский
комментарий справа. Комментарии выравниваются примерно по одному-двум уровням tab,
но физически используются пробелы; длинные строки — разумные исключения.
До `#` минимум два пробела. Не растягивайте весь блок из-за одного длинного поля.

Пустая строка разделяет законченные шаги: проверку, подготовку, I/O, обновление
состояния и обработку ошибки. Комментарий относится к следующему шагу, а не прилеплен
к предыдущему. Связанные присваивания не нужно разрывать после каждой строки.
Большие методы должны иметь достаточно русских пояснений для чтения через месяцы.

В конце неисполняемого модуля есть main guard с сообщением, что файл не предназначен
для запуска. Tests предлагают pytest, CLI вызывает main. В __init__.py guard не нужен.
Массовые механические правки проверяйте AST-сравнением; правила checker защищены
отрицательными regression tests. Формальная проверка не заменяет чтение комментариев.
