Автор: Sergey Fundobny (silverbull@mail.ru) + GPT-6

Дата и время последнего изменения: 261001-112704

## Текущее состояние проверки

28.09.2026 пользователь подтвердил получение smoke на телефоне с бесплатным
аккаунтом без резервирования темы. Это успешная проверка исходящего адаптера.
Закрытый доступ к теме пока не настроен; ниже описан переход к закрытому каналу.

## Что именно нужно настроить

Для Remote Watch нужны три значения: адрес сервера, имя topic и токен отправителя.
Для телефона нужна подписка на тот же сервер/topic с правом чтения.
Случайное имя темы и наличие токена сами по себе не закрывают доступ другим людям.

Выберите один из двух вариантов ниже. Собственный сервер позволяет отдельно
разрешить приложениям запись, а телефону чтение. На ntfy.sh инфраструктуру
обслуживает провайдер, а возможность закрыть тему зависит от резервирования.

## Вариант 1: ntfy.sh

1. Откройте веб-приложение ntfy.sh и войдите в свою учётную запись.
2. Проверьте возможность **Reserve topic** / резервирования темы. На публичном
   сервисе приватные зарезервированные темы относятся к платным возможностям;
   обычная публичная тема не становится закрытой после создания access token.
3. Зарезервируйте, например, `remote-watch-alerts`. В настройках доступа для
   остальных пользователей выберите запрет чтения и записи.
4. В разделе **Account → Access tokens** создайте токен для Remote Watch.
   Сохраните его только в `credentials.local.json`, в `ntfy.token`.
5. В том же файле задайте `ntfy.endpoint` равным `https://ntfy.sh`, а `ntfy.topic`
   — точному имени зарезервированной темы.
6. В Android-приложении ntfy добавьте доступ к этой учётной записи и подписку
   на тот же сервер/topic. Затем запустите `python -m remote_watch.diagnostics.smoke ntfy`.

Наличие резервирования проверяйте в своём аккаунте; тариф и покупку эта инструкция
не выбирает. Источники: [резервирование в веб-приложении](https://docs.ntfy.sh/subscribe/web/),
[условия ntfy.sh](https://docs.ntfy.sh/terms/),
[создание access token](https://docs.ntfy.sh/publish/#access-tokens).

## Вариант 2: собственный ntfy

Ниже предполагается уже работающий HTTPS-сервер ntfy. Команды выполняются
на нём, с его `server.yml` и правом записи в ту же базу пользователей.
При Docker выполняйте CLI внутри соответствующего контейнера с теми же томами.

В `/etc/ntfy/server.yml`:

```yaml
auth-file: "/var/lib/ntfy/user.db"
auth-default-access: "deny-all"
```

Примените конфигурацию перезапуском своего сервиса. Создайте два обычных пользователя;
пароли CLI запросит интерактивно:

```sh
ntfy user add rw-publisher
ntfy user add rw-phone
ntfy access rw-publisher remote-watch-alerts write-only
ntfy access rw-phone remote-watch-alerts read-only
ntfy token add --label=remote-watch rw-publisher
```

Скопируйте выданный токен в локальное `ntfy.token`, имя темы — в `ntfy.topic`,
адрес своего HTTPS-сервера — в `ntfy.endpoint`. Токен получает права пользователя;
отдельные права только одному токену здесь не задаются. Поэтому приложениям
выделен обычный пользователь с правом записи, а не администратор.

На телефоне настройте пользователя `rw-phone` для своего сервера и подпишитесь
на `remote-watch-alerts`. Пароль телефона и токен отправителя — разные credentials.

Команды и модель прав: [официальная настройка доступа ntfy](https://docs.ntfy.sh/config/#access-control).

## Проверка

Из корня Remote Watch:

```powershell
python -m remote_watch.diagnostics.smoke ntfy
```

После сообщения о приёме проверьте телефон. Затем проверьте тему без авторизации:
для закрытого topic анонимное чтение и публикация должны быть запрещены.
Не включайте рабочие логи, пока это не подтверждено.

Если возвращается `permanent_failure`, сначала проверьте соответствие сервера
и токена, имя topic и права отправителя. Если API принял сообщение, но телефон
молчит, проверьте сервер/topic подписки, авторизацию читателя и фоновые ограничения
Android. Для своего сервера важно instant delivery; детали зависят от сборки
приложения. Источник: [Android instant delivery](https://docs.ntfy.sh/subscribe/phone/#instant-delivery).

Развёртывание сервера, покупка тарифа и изменение ACL этой задачей автоматически
не выполняются. Полевая проверка по всем регионам: [CHANNELS.md](CHANNELS.md).
