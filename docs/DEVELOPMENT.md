## При начале реализации

- Единственный источник package metadata/version/dependencies — pyproject.toml.
- Layout src/remote_watch; public exports минимальны, internals не обещают стабильности.
- Tests разделяются на unit, contract и opt-in integration.
- Core не требует provider SDK; extras подключаются при использовании адаптера.
- Pytest запускается без сети и credentials по умолчанию.
- Ruff начинает с проверок ошибок и imports; конкретные правила согласуются
  с [CODE_STYLE.md](CODE_STYLE.md), line length 115. Ruff formatter не включается.
- Версия 0.1 предназначена только для личного/закрытого использования по решению
  владельца. Перед публичным распространением отдельно выбрать лицензию;
  не копировать лицензию соседнего проекта.

## Работа над изменением

1. Прочитать относящиеся к задаче документы согласно AGENTS.md.
2. Проверить рабочее дерево и сохранить несвязанные изменения пользователя.
3. Изменять минимальный необходимый набор компонентов, обновить шапки документов.
4. Изменения гарантий, API, security или границ фиксировать в архитектуре/ADR.
5. Проверить поведение тестами соответствующего уровня и документацию.
6. Проверить diff, отсутствие секретов, состав staged files и создать осмысленный commit.

Нельзя записывать в чужие проекты при изучении примеров. Интеграция реального
приложения выполняется отдельной задачей и коммитом в его репозитории.

## Проверки

С dev7 поддерживаемая проверка wheel из sdist перенесена в tools/validate.py.
Локальные команды, отчёты и матрица GitHub Actions: [CI.md](CI.md).
Одноразовые скрипты в build больше не являются единственным способом проверки.

Для изменений только документации: существование относительных ссылок,
согласованность scope/defaults, кодировка/BOM/newlines, отсутствие незаполненных
маркеров и git diff --check. Проверка плана не означает проверку кода или сети.

После появления реализации базовые команды из корня:

```powershell
python -m ruff check .
python -m pytest -q
python -m build
```

Сначала выполняются целевые проверки изменённого поведения, затем обязательный
набор проекта. Wheel проверяется в чистом окружении без optional extras и с ними.
Live-provider тесты не добавляются к обычной команде автоматически и не используют
credential из репозитория. Правила приёмки: [VALIDATION.md](VALIDATION.md).
Одноразовые smoke запускаются явно и читают игнорируемый локальный файл по [SMOKE.md](SMOKE.md).
Не читать и не выводить этот файл обычными командами просмотра; проверка схемы не должна раскрывать значения.

## Git и локальные данные

Основная ветка — main. Initial commit содержит только документацию и настройки Git.
Удалённый origin и публикация не создаются автоматически. Автор Git берётся из
существующей конфигурации пользователя; данные автора не выдумываются.

.gitignore исключает окружения, кеши, сборки, runtime data и local credentials.
Ignore не заменяет просмотр staged diff. .gitattributes задаёт окончания строк.
Секреты не должны появляться даже в первом коммите. Если когда-либо понадобится
очистка чужой истории или отзыв старых токенов, это отдельная работа с владельцем;
история fin-data в этой задаче не проверялась и не менялась.
