Автор: Sergey Fundobny (silverbull@mail.ru) + GPT-6

Дата и время последнего изменения: 260928-184554

## Результат и объём

Библиотечная часть 0.1 реализована для личного использования. Просмотрены core-модели,
валидация, регистрация команд, нормализация LogRecord, routing, runtime и lifecycle,
retry/TTL, HTTP transport, Telegram/ntfy, smoke, упаковка и пользовательские инструкции.
Это ревью кода и контрактов с offline-проверками; оно не является полевым испытанием
всех серверов или независимым аудитом безопасности.

Добавлен последний запланированный пользовательский слой: RemoteWatcher с обычным
Logger/LoggerAdapter, необязательными консолью и rotating file, sync/async lifecycle.
Исполняемые примеры показывают отдельное приложение и существующую logging hierarchy.
Core по-прежнему не зависит от конкретного провайдера или обязательного сетевого SDK.

## Исправленные замечания

| Замечание | Последствие | Исправление и проверка |
| --- | --- | --- |
| Последовательное закрытие каналов | Медленный close мог исчерпать срок и помешать закрытию здорового клиента | Ограниченное параллельное закрытие с общим deadline; тест двух каналов, один из которых зависает в close |
| Стандартный append FileHandler может открыться после close | Запоздавший logging-вызов мог вновь открыть собственный журнал после stop | Собственный rotating handler проверяет закрытие под lock стандартного handle; регрессионный тест запоздавшего вызова |
| Не был реализован шаг пользовательской настройки | Приложениям требовалось вручную связывать logger, handlers и runtime | RemoteWatcher; тесты владения, ротации, отката и отмены async lifecycle |
| Документация команд и статусов отстала от реализации | Можно было принять работающий runtime за будущий API, а регистрацию команд — за их исполнение | Исправлены текущий API, границы 0.1 и порядок внедрения приложения |

## Сохранённые ограничения

- Очереди находятся в памяти; переполнение, авария, expiry и остановка могут потерять
  событие до первой попытки. Неизвестный исход с повтором может дать дубликат.
- Принятие сервисом не подтверждает показ или прочтение. Пользователь подтвердил
  получение обоих smoke на Android, но длительный простой и все регионы не проверены.
- Бесплатная тема ntfy без резервирования не считается закрытым каналом. Наличие
  токена отправителя само по себе не доказывает закрытый доступ к теме.
- Контракт адаптера требует неблокирующих async-методов и поддержки отмены.
  Зависший синхронный код нельзя принудительно остановить Python-потоком;
  runtime сообщает FAILED/TimeoutError при нарушении срока остановки.
- Локальные handlers работают по правилам logging. Их write/flush не ограничены
  сетевым deadline; один файл с ротацией не предназначен для нескольких процессов.
- Logger должен пропускать нужный уровень. RemoteWatcher сохраняет чужую настройку;
  несколько владельцев на одном logger или его предках могут дать несколько отправок.
- Redactor обрабатывает удалённый текст сообщения/исключения. Он не очищает локальный
  журнал или произвольные metadata; identity и metadata не должны содержать секретов.
- Регистрация callbacks реализована, получение и выполнение команд отсутствуют.
  Удалённые команды, relay, durable outbox и автоматический fallback остаются за 0.1.

## Проверки и последующая работа

Точные результаты сборки, тестов и live-подтверждений: [VALIDATION.md](VALIDATION.md).
Локально доступен Windows/Python 3.12.2. Разбор грамматикой Python 3.10 не заменяет
запуск на этом интерпретаторе; Python 3.10 и Linux требуют отдельной runtime-проверки.
Автоматический перенос секретов, публикация пакета и изменение глобальных зависимостей
для этой проверки не выполняются.

Владелец выбрал личное/закрытое использование без публичной публикации. Открытая
лицензия не выбиралась; classifier Private :: Do Not Upload сохраняется.
Подключение реального приложения отложено до минимального контура команд, чтобы
обновить интерфейс приложения полностью. Эти пункты больше не являются недостающей
реализацией исходящих уведомлений 0.1.

Внешние проверки остаются открытыми: запуск на минимальном Python и Linux,
полевой сценарий всех серверов/Android, а перед рабочими чувствительными уведомлениями —
настройка и проверка закрытого ntfy topic по [NTFY_SETUP.md](NTFY_SETUP.md).
