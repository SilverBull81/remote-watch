# Свежесть команд без синхронизации часов приложений

Version 1.0.0

Автор: Sergey Fundobny (silverbull@mail.ru) + GPT-6

Дата и время последнего изменения: 260930-220144

## Реализовано в 0.3.0.dev2

Владелец выбрал resume/suspend одним сообщением. Проверка в command_time
использует отметку провайдера и достоверный интервал UTC на hub. Часы Windows
не меняются, UTC приложений не сравнивается. Подтверждение CommandChallenge
не требуется и не включается автоматически; прежний helper оставлен совместимым.

Это рабочие отдельные компоненты, ещё не встроенные в командные endpoints:
TrustedClock, FreshnessPolicy, TimeSource и адаптер HttpsDateTimeSource.
Конструкторы не обращаются к сети. Реальный Telegram source появится в 0.3.5.

## Оценка времени

TimeSample задаёт нижнюю и верхнюю границы UTC в момент observed_at на локальных
монотонных часах. TrustedClock добавляет прошедшее время, расширяя интервал
на допустимый дрейф. Системный time.time не читается. Показание не сохраняется
на диск и не восстанавливается после перезапуска процесса.

| FreshnessPolicy | По умолчанию | Максимум |
| --- | --- | --- |
| max_age | 120 с | 300 с |
| sample_ttl | 300 с | 3600 с |
| max_uncertainty, полная ширина интервала | 5 с | 10 с |
| drift_ppm, допустимый дрейф | 100 ppm | 1000 ppm |
| future_tolerance | 2 с | 5 с |

Эти величины — явные эксплуатационные допущения. Проверенный сертификат
удостоверяет сервер, но не точность его часов. Источник должен действительно
укладываться в заявленную accuracy; локальный отсчёт — в drift_ppm. Политика
не получает accuracy из самого HTTP-заголовка и не обучается на входящих командах.

Источник выбирается владельцем. Никакой публичный сервис не назначен автоматически;
его доступность и точность на конкретной LV VM пока не проверялись.
Можно передать свой TimeSource, возвращающий TimeSample после аутентифицированного
измерения. Использовать отметку последнего входящего сообщения как текущее время нельзя.

## HTTPS-источник

HttpsDateTimeSource находится в remote_watch.adapters.time_source.
Для запроса нужен optional aiohttp: установка remote-watch[gateway] уже включает его.
Импорт адаптера не требует aiohttp; импорт core остаётся без дополнительных зависимостей.

```python
from remote_watch.adapters.time_source import HttpsDateTimeSource

# Только конфигурация: пример не выполняет запрос и не утверждает существование URL.
source = HttpsDateTimeSource("https://time.example.invalid/clock", accuracy=0.5, timeout=5)
```

Адаптер отправляет один HEAD на явно настроенный HTTPS URL. Контракт origin:
ответ 200/204, ровно один Date с UTC, сформированный для этого запроса;
часы origin укладываются в accuracy. Перенаправления, Age и некорректные Date
отклоняются. URL получает случайный query-параметр, запрос запрещает кеширование.
Endpoint должен поддерживать этот режим. Произвольный сайт с Date не становится
доверенным источником автоматически. Основа формата:
[RFC 9110, Date](https://www.rfc-editor.org/rfc/rfc9110.html#name-date).

TLS всегда проверяется, включая имя сервера. Можно передать проверяющий SSLContext
с нужным CA. Cookies, proxy из окружения, redirects и скрытые retries выключены.
Тело HEAD не читается; поля заголовков ограничены. Весь запрос ограничен timeout,
по умолчанию 5 с, максимум 30 с. Одновременно объект выполняет не более одного
измерения; конкурирующий вызов отклоняется, а не создаёт очередь.

Пусть S — секунда Date, A — accuracy, R — весь round trip.
При получении ответа принимается интервал `[S − A, S + 1 + A + R]`.
Секунда учитывает округление Date, полный RTT даёт консервативную верхнюю границу.
Слишком широкий интервал TrustedClock не принимает. Ошибки источника скрывают
URL/ответ/исключение; наружу выходит TimeUnavailable с фиксированным текстом.

## Проверка сообщения

```python
from remote_watch.command_time import TimeSample, TrustedClock

now = [100.0]
clock = TrustedClock(clock=lambda: now[0])
clock.install(TimeSample(lower_utc=1000000, upper_utc=1000002, observed_at=100))
decision = clock.check(message_date=999990, hub_epoch="a" * 32)
assert decision.reason is None
assert decision.deadline.remaining(100, "a" * 32) == 108

now[0] = 208
assert decision.deadline.remaining(now[0], "a" * 32) == 0
```

message_date — целая секунда исходного сообщения, для Telegram это
[message.date](https://core.telegram.org/bots/api#message). Для расчёта возраста
используется самая поздняя возможная граница текущего UTC. Остаток равен max_age
минус этот консервативный возраст, максимум max_age. Этот остаток становится
локальным CommandDeadline; хранение, очередь, запрос разрешения и доставка
не начинают его заново. Истёкший на границе deadline срок уже недействителен.

Результаты отказа: time_unavailable, too_old, future. Нет показания, чрезмерная
погрешность, срок годности или возврат monotonic назад запрещают приём.
Неудачный refresh снимает прежнее доверие; откат часов тоже не восстанавливает
его автоматически. Нужно новое успешное измерение. Периодический refresh и его
жизненный цикл подключит hub на этапе 0.3.3, отдельного скрытого потока сейчас нет.

Проверка свежести не аутентифицирует пользователя и не заменяет ACL. Авторизация,
парсер и явное сопоставление source/actor/chat будут выполняться до приёма команд.
Для отклонённого события hub должен атомарно сохранить решение и cursor через
store.admit с request=None, затем ответить пользователю понятной причиной.
Время набора текста на телефоне без связи не удостоверяется отметкой Telegram.

Компоненты TrustedClock и HttpsDateTimeSource принадлежат одному командному loop;
их не следует вызывать с application logging threads. Слой SQLite синхронный и
будет обслуживаться отдельно. См. [COMMAND_STORAGE.md](COMMAND_STORAGE.md).
