Version 1.0.5

Дата и время последнего изменения: 260930-171719

## Задача

Remote Watch — проект Python-библиотеки для стандартного логирования,
асинхронных уведомлений и, на следующем этапе, адресных команд приложениям.
Пользователь запускает несколько собственных приложений на удалённых серверах
в разных странах и получает важные сообщения на Android-телефоне. Часть серверов,
по сообщению пользователя, не может отправлять сообщения в Telegram.
Поэтому первая версия должна включать реально проверенную альтернативу.

Исходная идея возникла при пересмотре `fin-data`, но интерфейс его `TelegramBot`
не является требованием совместимости. Приложения уже используют обычный Logger;
изменение их настройки и вызовов при переходе принято осознанно. Shim, наследование
старого бота и зависимость от `fin-data` не планируются.

## Пользовательский результат

1. Обычные методы logger записывают сообщения в настроенные локальные handlers
   и выбирают удалённые назначения.
2. Важное событие приходит на телефон и явно обозначает приложение и instance.
3. Несколько процессов могут отправлять в один чат или topic.
4. Настройки каждого удалённого назначения выбирают прямую доставку или relay.
   Изменять вызовы logger при смене способа доставки не требуется.
5. Пользователь может подключить свой адаптер без изменения core.
6. На этапе команд авторизованный пользователь обращается к конкретному instance
   через общий чат и получает связанный с запросом ответ.
7. Приложение передаёт собственный набор команд при создании объекта: простым
   словарём callbacks/partial или расширенными CommandSpec. Фиксированный встроенный
   перечень команд не ограничивает возможности приложения.

Пакет не заменяет мониторинг, метрики, tracing и управление инфраструктурой.
Не предусматриваются произвольный shell, Python evaluation и гарантия exactly-once.

## Принципы интерфейса

Основной интерфейс — стандартный `logging.Logger`. Remote Watch добавляет handler,
управляемый runtime и удобную явную настройку консоли/файла/уведомлений.
`LoggerAdapter` допустим для контекста, обязательный подкласс Logger не нужен.
Существующее логирование приложения не перенастраивается автоматически.

Идентичность (`service`, `environment`, `region`, `host`, `instance_id`) задаётся
при создании runtime. Вызов logger может задавать `notify`, `topic`, `tags`,
но не учётные данные, chat ID или подмену identity. Вызов с `notify=True` не
восстанавливает запись, отфильтрованную уровнем самого logger.

## Первая версия: 0.1

- Независимый от провайдеров core, fake-канал и явное подключение custom adapters.
- Стандартное logging, независимый тракт уведомлений и локальные handlers.
- Telegram и ntfy как первые исходящие адаптеры. Выбор ntfy — проектная
  рекомендация; получение на телефоне уже подтверждено, все серверные регионы
  ещё проверяются отдельно.
- Маршрутизация по уровню, `notify`, теме, тегам и identity.
- Ограниченные очереди, таймауты, повторы, обработка rate limit и завершение работы.
- Наблюдаемые потери и ошибки без рекурсивных уведомлений.
- Типизированные Python-настройки; без обязательного формата конфигурационного файла.

В 0.1 реализуется прямая доставка. Архитектура и модель назначения уже разделяют
провайдера и способ доставки; relay становится доступным в 0.2. Попытка включить
нереализованный режим должна давать ошибку конфигурации, а не прямую отправку.

## Последующие этапы

| Этап | Результат |
| --- | --- |
| 0.2 | Необязательный outbound relay и доставка через него для выбранных назначений |
| 0.3 | Command hub: общий чат, авторизация, проверка состояния и resume/suspend, коррелированный ответ |
| Далее | Matrix как чат для уведомлений и команд, затем группы и расширенные операции |
| По подтверждённой потребности | Durable outbox, batching, deduplication, fallback, email, webhook, Apprise |

Outbound relay и command hub — разные возможности gateway. Использование одной
не включает другую автоматически. Их разрешено разворачивать вместе.

Matrix — следующая приоритетная интеграция для двустороннего общения.
MAX исключён из текущего плана по выбору пользователя. Почта — резервный вариант.
Выбор и альтернативы разобраны в [CHANNELS.md](docs/CHANNELS.md).

## Границы гарантий

Доставка 0.1 хранит работу в памяти: возможны потери до первой отправки,
при переполнении, аварии, expiry и остановке. Повторы могут приводить к дубликатам.
Подтверждение провайдера не означает, что уведомление показано или прочитано.
Удалённая доставка не выполняет сеть и не ждёт свободного места в потоке logger;
форматирование, синхронизация и локальные handlers имеют собственную стоимость.

Доступность сервиса в России или другой стране не выводится из названия протокола.
Нужна проверка полного пути «конкретный сервер → сервис → конкретный телефон».

## Приёмка

Первая версия принята, когда обычный logger отправляет выбранные события через
оба адаптера, ntfy проверен на целевых сетях и Android-телефоне, несколько instances
различимы в общем назначении, а сбой одного назначения не останавливает остальные.
Очереди, повторы и shutdown ограничены; потери видны; unit-тестам не нужны секреты
или сеть. Сценарии и границы проверок: [VALIDATION.md](docs/VALIDATION.md).

Библиотечная часть 0.1 реализована для личного использования; получение обоих
smoke на Android подтверждено 28.09.2026. У ntfy бесплатный аккаунт без резервирования
темы. 30.09.2026 владелец принял базовую прямую доставку после примерно 12 часов
наблюдения RU/LV и проверки Android. Полные сутки и выключение телефона
не требуются для текущей приёмки; границы указаны в [FIELD_SMOKE.md](docs/FIELD_SMOKE.md).
Перенос реального приложения по решению владельца отложен до минимальных команд.

## Открытые вопросы

- Базовый relay RU → LV → Telegram подтверждён владельцем на телефоне 30.09;
  длительный mixed, автозапуск и восстановление VM остаются эксплуатационными проверками.
- В 0.3 включены проверка состояния и resume/suspend; до исполнения формализовать
  повторы, неизвестный исход и время при расходящихся часах VM, см. ADR 0009.
- Расширение проверяемых сред при необходимости: матрица Windows/Linux × Python
  3.10/3.12 × core/extras уже прошла, см. [VALIDATION.md](docs/VALIDATION.md).
- При решении о публичном распространении потребуется выбрать лицензию.
  Для 0.1 владелец выбрал личное/закрытое использование без публикации.
- SDK и политика encrypted rooms для Matrix до начала его реализации.
- Формат хранения и гарантии durable outbox, если возникнет потребность.
